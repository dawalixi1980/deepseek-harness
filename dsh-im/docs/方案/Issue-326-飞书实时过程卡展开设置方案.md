# Issue 326 飞书实时过程卡展开设置方案

日期：2026-10-09（Asia/Taipei）。状态：已实施，自动化与本机飞书验收通过；手机端另行补测。

关联：[Issue #326](https://github.com/xmanrui/dsh-im/issues/326)。代码基线：dsh-im 4.37.0。

在“飞书 → 更多设置 → 通用”增加“展开思考过程”和“展开工具摘要”两个开关，按机器人保存。复用现有设置行、滑动开关、即时保存、配置存储和卡片生成机制，让手机用户能够选择更适合自己的过程展示方式。

机器人卡片内容及卡片上已有的“任务过程展示”入口保持原样。

## 需求与范围

当前实时过程卡在运行期间展开工具摘要、折叠思考过程。`stepStreamCard()` 中的规则为：

```js
expanded: block.kind === 'tools' && running
```

本次将两个面板的运行中展开状态改为可配置，保留任务结束后的统一收起行为。

- 两个开关分别控制思考过程和工具摘要，支持四种组合。
- 只在飞书机器人的通用页展示，其他渠道保持现状。
- 每个机器人独立保存，不增加全局继承、会话级覆盖或批量同步。
- 保留现有过程内容的来源和组织方式，只改变面板的展开状态。
- 不移动机器人卡片上的任何内容，不增加页面、页签或额外设置入口。

## 页面布局与文案

入口：**IM 机器人 → 飞书 → 对应机器人 → 更多设置 → 通用**。

在现有“消息处理方式”下方增加两行，保持左侧文案、右侧控件的布局。

| 设置名称 | 初始状态 |
| --- | --- |
| 展开思考过程 | 关闭 |
| 展开工具摘要 | 开启 |

两个开关之间不显示分隔线，作为同一组呈现；下方共用一条说明，说明下方保留分隔线作为整组的边界：

> 仅对实时过程卡生效，任务结束后自动收起。

标签不重复使用“默认”，也不在开关旁重复显示“默认开／默认关”。状态由控件直接表达。

两个开关在飞书通用页固定显示，允许提前设置。当前使用其他过程展示模式时仍可保存偏好，之后切换到实时过程卡即按配置展示；修改开关不会自动切换过程展示模式。

## 样式与交互复用

布局复用 `plugin-src/client/bot-general-settings.js` 已有的设置行：

- `dim-botGeneralList`、`dim-botGeneralRow`：列表、行间距、分隔线和左右布局。
- `dim-botGeneralText`、`dim-botGeneralTitle`、`dim-botGeneralHelp`：标题与说明文字。
- `dim-botGeneralControl`：右侧控件对齐。

开关复用插件已有的 `dim-contextSwitch` 样式和原生 `input[type="checkbox"]` 配合 `role="switch"` 的实现方式。沿用 32 × 19 像素尺寸、主题蓝色开启态、灰色关闭态以及现有主题变量，不引入新的组件库或视觉风格。

文字标签与控件关联，支持点击文字、键盘聚焦及空格切换。仅补齐本区域必要的禁用态和焦点态样式，避免改动其他页面的开关表现。窄窗口下文案可换行，右侧开关保持完整显示。

复用通用页已有的即时保存流程：

1. 打开页面时通过现有 `connection.status` 读取当前机器人的配置，读到服务端值后才允许修改。
2. 点击开关后更新界面并自动保存，不增加保存、取消或重置按钮。
3. 保存期间使用现有忙碌状态禁用操作，防止连续请求互相覆盖。
4. 成功后以服务端返回值更新界面；失败则恢复上次保存的值，并显示现有样式的错误提示。
5. 初次读取失败时保持不可编辑，沿用“重新读取”入口；切换机器人时丢弃旧页面的迟到响应。

新增文案加入现有中英文翻译表。保存成功不新增弹窗或额外确认步骤。

## 配置与管理接口

在现有飞书机器人配置中增加一个对象：

```js
stepCardPanels: {
  thinkingExpanded: false,
  toolsExpanded: true,
}
```

沿用 `PluginConfigStore` 的机器人配置文件及保存方式，不新增存储文件、数据库或配置版本。

在现有 `src/channels/feishu/step-push-mode.mjs` 中补充小型的默认值和归一化函数，供配置读取、状态返回与运行时复用。分别判断两个字段是否为布尔值，缺失或非法时回退到对应初始值；明确保存的 `false` 必须保留，不能用 `value || true` 处理工具开关。

读取继续使用现有 `connection.status`，在当前机器人的状态中返回 `stepCardPanels`。客户端状态归一化同步保留该对象。

新增一个飞书保存接口 `bot.step-card-panels.set`，一次提交两个布尔值：

```js
{
  botId,
  stepCardPanels: {
    thinkingExpanded: false,
    toolsExpanded: true,
  },
}
```

接口沿用现有飞书管理接口的权限、参数校验及错误返回机制。校验机器人标识、字段白名单和两个布尔值；写入请求中的非法类型直接拒绝，不静默转换。

控制器复用按机器人串行保存的机制：先成功写入配置，再更新运行实例，最后返回最新状态。保存失败时不更新运行时配置。机器人离线时也可以保存，下一次启动从配置恢复。

已有机器人的配置缺少该对象时，继续保持“思考折叠、工具展开”。新机器人使用同一初始值。重连、凭据重新绑定和授权更新继续保留已经保存的偏好。

升级、启动和打开设置页只在内存中补齐缺省值，不为新增开关主动改写配置文件。用户无需重新设置，也无需先了解这两个开关。之后正常保存配置时，现有存储机制可以补写缺省字段，原有配置值与展示行为保持一致。修改这两个开关不会开启任务过程展示，也不会改变原先选中的展示模式、消息处理方式或其他机器人的偏好。

## 运行时与卡片展示

沿用现有配置传递链路：

```text
通用设置页
→ 飞书管理接口
→ MultiBotController
→ PluginConfigStore 保存
→ FeishuRuntime 更新配置
→ FeishuHarnessBridge
→ stepStreamCard
```

参照现有 `setStepPushMode()` 的方式，在 Runtime 和 Bridge 中保存并更新这组配置；在生产环境启动 Runtime、Runtime 创建 Bridge 时传入配置。不重建连接或消息桥接实例。

`stepStreamCard()` 接收额外的面板设置参数，只修改现有面板的 `expanded` 判断：

| 卡片状态 | 展示规则 |
| --- | --- |
| `running` | 思考面板读取 `thinkingExpanded`，工具面板读取 `toolsExpanded` |
| `completed` | 沿用现有收起规则，两个面板放入折叠的“过程详情” |
| `stopped` | 沿用现有收起规则，两个面板放入折叠的“过程详情” |
| `sealed` | 超长内容产生的已封存卡片继续使用现有收起规则 |

空面板继续不显示，最终答案仍按现有方式展示。原生实时直播、逐步消息和不显示过程等模式不读取这组面板偏好。

保存后热更新配置，从下一次正常卡片刷新开始生效。无需重连，也不因为修改开关而主动发送消息或额外刷新卡片；已经完成的历史卡片保持原样。

以下位置必须传入一致的配置：

- 实时卡片发送及更新时的内容生成。
- `splitStepStreamCardBlocks()` 内部调用渲染函数进行体积计算的位置。
- 会话同步镜像保存的 `lastContent` 生成位置，以及恢复后继续生成卡片的路径。

继续复用现有分片、发送队列、镜像保存和恢复机制，只补充参数传递，避免显示内容与分片计算使用不同设置。

卡片内的手动展开、折叠继续沿用飞书客户端现有行为。本次不增加点击状态的服务端记录或跨消息记忆。发布前实测持续刷新对手动操作的影响，不预先承诺客户端会保留该状态。

## 实施顺序与验收

先补齐配置及管理接口，再接通 Runtime、Bridge 和卡片生成，最后接入通用页与翻译。沿用现有测试文件及夹具补充行为验证。

自动化验收重点：

- 旧配置、缺失字段及明确保存的 `false` 均按预期处理；不同机器人互不影响。
- 保存和重新加载后值一致，运行实例接收到正确配置，保存失败不会更新运行时。
- 四种开关组合在运行中均正确，完成、停止和已封存状态仍保持收起规则。
- 卡片分片与镜像内容使用同一配置，既有最终答案及过程内容完整保留。
- 页面只在飞书显示新增开关；读取失败不可编辑，保存失败回退，保存中禁止重复操作，切换机器人不串状态。
- 现有消息处理方式、其他渠道通用页及机器人卡片内容保持原行为。
- 中英文文案、键盘操作、浅色和深色主题、窄窗口布局符合现有插件样式。

实现完成后运行相关回归测试及项目现有 `npm run check`，检查构建、测试和发布包验证结果。

飞书手机端实测一个包含过程说明和工具调用的长任务，验证“思考展开、工具折叠”及其他组合，观察持续刷新、手动折叠、任务完成和停止后的效果。重新打开设置、重启或重连后复验配置保留情况。

验收通过标准为：两项偏好能够可靠保存并正确控制运行中的实时过程卡，结束后仍自动收起，新增控件与插件样式协调，机器人卡片内容保持原样。
