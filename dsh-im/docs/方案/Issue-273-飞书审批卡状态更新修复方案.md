## 2. 三处功能改动

### 2.1 审批队列：在现有结果通知处提供一个可选回调

文件：`src/channels/shared/harness-approval.mjs`。

在 `handleRequested(interaction, context)` 中接收可选的 `context.onResolved(resultText)`，保存到现有 `pending` 对象。没有提供回调的渠道继续使用文字回执。

把重复的“发送审批结束文案”代码收进一个小型私有方法，例如 `#notifyResolved(pending, outcome, send = pending.send)`：

1. 复用 `pending.resolutionNotified` 去重，在第一次异步调用前标记，保证同一审批只通知一次。
2. 使用 `approvalOutcomeText(outcome)` 生成现有结果文案。
3. 调用可选的 `pending.onResolved(resultText)`；异常只记录警告。
4. 通过原有 `send` 发送同一份文字回执，保留原来的失败降级。

各调用点保留原来的发送目标；已有提前捕获 `send` 的分支继续把它传入。回调失败不阻断文字回执、下一项审批或已确认的审批结果。

只在当前已有结果通知的位置替换重复代码：

| 现有路径 | 传入的结果 | 卡片行为 |
| --- | --- | --- |
| `#submit()` 提交成功 | 本次实际提交的 outcome | 显示批准或拒绝 |
| `#submit()` 返回 `interaction-not-pending` | 通用已处理结果 | 移除按钮，不猜测批准或拒绝 |
| `handleResolved()` 收到其他客户端的处理结果 | `resolution.outcome` | 显示确认的结果，未知时显示已处理 |
| `closeRoute()` 确认拒绝成功 / 已不再待处理 | rejected / 通用已处理结果 | 更新已展示的卡片 |
| `#present()` 发送完成时审批已关闭 | 现有 `pending.closedOutcome` | 补更新刚发出的卡片 |

普通提交失败仍走原来的失败提示和重试路径，不调用结束回调。`closeRoute()` 未能确认拒绝结果时沿用现有日志处理，不虚构“已拒绝”。

保留 `presentationTask`、`activationTask`、`#transition()` 的现有等待位置和执行顺序。通知方法不自行等待 `presentationTask`，避免从 `#present()` 内调用时等待自身。未展示的队列项结束时，不额外创建卡片。

**无需调整 `submitByApprovalId()` 的返回契约。** 目前它的 `true` 表示已找到审批并尝试提交，不保证提交成功。本方案直接挂接实际结果通知，不把这个布尔值作为刷新依据，也不在按钮处理分支重复更新卡片。

### 2.2 飞书桥接：保留消息 ID，复用原地更新方法

文件：`src/channels/feishu/bridge.mjs`。

在 `#handleInteraction()` 的审批渲染上下文中，用局部闭包保存两项数据：

- `approvalCardMessageId`：现有 `#sendCard()` 成功返回的消息 ID。
- `approvalCardData`：发卡时使用的工具、操作参数、原因、审批 ID。

使用闭包让这两项数据跟随现有 pending 的渲染和结束回调生命周期，不新增全局 Map、持久化字段或清理定时器。卡片内容在首次渲染时构建，完成时直接复用；payload 从现有 `pending.interaction.payload` 读取。

提供 `onResolved(resultText)`：

```js
onResolved: async (resultText) => {
  if (!approvalCardMessageId) return;
  await this.#patchCardMessage(
    chatId,
    approvalCardMessageId,
    approvalCard({ ...approvalCardData, resolvedText: resultText }),
  );
}
```

继续复用 `#patchCardMessage()` 的整卡替换、错误日志和失败返回机制，和提问卡完成后的更新方式一致。可把该方法现有日志中的 `answered-state` 改成通用描述，便于区分为交互卡更新失败。

发卡失败后仍按原逻辑降级为文字；没有成功取得卡片消息 ID 时，结束回调直接返回。文字审批会进入同一队列提交路径，因此也会更新之前发送的卡片。

卡片更新失败不重发新卡、不重新提交审批，保留文字回执作为降级。使用 `#patchCardMessage()`，而非具有发送新卡降级行为的 `#sendCard({ updateMessageId })`。

### 2.3 审批卡模板：增加一个可选结果文本参数

文件：`src/channels/feishu/feishu-cards.mjs`。

给现有 `approvalCard()` 增加 `resolvedText` 参数：

- 标题、工具、参数、原因沿用现有布局和截断规则。

无需新建第二套审批卡模板、状态枚举或翻译文案；继续复用 `cardWith()`、`markdown()` 和现有按钮辅助方法。
