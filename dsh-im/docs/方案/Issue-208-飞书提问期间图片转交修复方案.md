# Issue #208：飞书提问期间图片转交修复方案

日期：2026-09-29。基线：`80d5d49`。采用收到图片后结束本轮追问、将图片作为原会话新消息继续处理的方案。

## 真实复现

在本机飞书机器人“今天是牢梁”私聊测试，环境为 DSH 0.2.0-rc.1、dsh-im 4.30.0、模型 doubao-seed-2.1-pro。通过客户端发送指令，真实调用 `ask_user_question` 一次询问两题；出现第 1/2 题卡片后，通过“图片/视频”入口发送测试 PNG。

飞书显示图片发送完成，但机器人回复“请用文字回答当前问题。”，第一题仍待回答。状态文件新增该图片消息的去重 ID；Session 的最后事件仍是 `ask_user_question` 调用，没有工具结果、图片输入或回合结束事件。原始证据保存在本机 `~/.dsh-test-evidence/issue208-20260929/`，不提交配置、凭据和原始会话数据。

## 原因

`accept()` 将提问发起人的消息交给 `#processInteractionReply()`，后者先标记已处理，再用仅支持 `text` 类型的 `extractText()` 解析。图片和图文消息直接返回，既不提交答案也不进入普通图片处理流程。多题回答需全部收齐才提交，因而持续等待。宿主回答协议只保留选项和文字，不能靠增加一个图片字段完成修复。

## 最小实现

1. 限定飞书当前会话中提问发起人发来的真实图片或含图片的富文本。权限、群聊提及、会话隔离和审批决策沿用现有机制；不扩展到文件、语音或其他渠道。
2. 复用 `extractInboundMessage()` / `hasInboundImages()` 判断图片，保留图文中的文字及所有图片。图片不参与文字答案占位；通过现有交互队列与正在处理的文字答案保持顺序。
3. 为图片先在现有普通消息队列保留位置，再复用 `/stop` 的当前回合停止能力及待回答交互取消逻辑，解除原回合的等待。保留会话绑定，不调用 `/new`，不提交虚构答案。先保留队列位置，避免取消期间后来的图片或文字越过第一张图片。
4. 继续走现有普通消息处理、图片下载/落盘、模型输入及错误提示；图片直接进入普通队列，由该队列统一记录已处理状态和收尾 reaction，避免重复处理。并发消息、旧提问引用中的图片仍按普通图片处理，不被旧问题已结束的过滤器丢弃；旧文字回答和按钮保留原有失效保护。
5. 复用提问卡模板和原卡 patch，添加可选结束文案，移除当前题的按钮并说明将继续处理图片。更新失败只记录日志，不阻断图片；文字提示同样不阻断图片。
6. 若停止请求失败，图片保留在普通队列，恢复原提交状态并提示用户先回答或停止任务；若卡片答案正在提交，则继续保留提交状态，后续文字仍进入普通队列。不声称已经结束、不重建队列或自动重试。原回合结束后仍处理已排队的图片。

不增加持久化状态、新配置、后台任务、图片专用队列或新的 Harness 协议。只对既有交互取消方法增加可选 interaction ID，防止取消期间误清理后来的交互。
