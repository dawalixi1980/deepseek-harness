# Issue 300 飞书工作区名称显示优化方案

飞书的工作区选项改为优先显示 DSH 工作区名称，没有名称时显示文件夹名；重名时补充目录信息。主菜单下拉框和独立工作区列表共用标签规则，切换仍使用原来的绝对路径。

本方案采用现有客户端、工作区快照和卡片构建流程，只补充名称数据和标签生成。已修改 5 个现有生产源码文件，并更新对应构建产物，无新增依赖、配置项、持久化数据或后台任务。

需求来源：[Issue 300](https://github.com/xmanrui/dsh-im/issues/300)。整理与实施日期：2026-10-03。核查基线：本地 `e2f2434`，包版本 `4.34.2`。实施分支：`codex/issue-300-workspace-titles`。状态：代码已实施，自动化检查和用户指定的本机飞书机器人验收通过，具体范围见文末。

## 目标与显示规则

| 情况 | 显示规则 | 示例 |
| --- | --- | --- |
| 有有效 title | 使用清理后的 title | `策略研究` |
| title 缺失、非字符串或清理后为空 | 使用末级文件夹名 | `/data/交流区` 显示 `交流区` |
| 根目录没有末级文件夹名 | 使用根路径 | `/`、`C:\` |
| 名称重复 | 给重复项补路径末尾，仍重复则向上补一级 | `项目 · 客户A`、`项目 · 客户B` |
| 标签过长 | 中间省略，保留开头和结尾 | `长期策略研究…历史归档` |
| 省略后标签再次重复 | 在这些项的最前面加原列表序号 | `2. 长期策略…归档`、`3. 长期策略…归档` |

正常效果：

```text
主菜单下拉框
✓ 策略研究
  交流区
  项目 · 客户A
  项目 · 客户B

工作区列表卡
1. 策略研究（当前）
2. 交流区
3. 项目 · 客户A
4. 项目 · 客户B
```

名称和目录文字清理控制字符、换行和多余空白，使用卡片的纯文本字段。标签主体暂定最多 22 个 Unicode 码点，超出时保留前 11 个、一个省略号和后 10 个；序号和当前标记单独添加，不参与截断。该长度是本次显示策略，不是飞书官方限制，实际可读性需要手机验收。

重名判断包含 title 与文件夹名之间的冲突。同名项附加“父目录/末级目录”，仍重复则逐级补上级目录，到完整路径为止；当标签本身就是末级目录名时，附加部分省去重复的末级名称。例如 `/客户A/项目` 和 `/客户B/项目` 显示为表中的形式，而同一父目录下、title 都为“研究”的 `a`、`b` 显示为 `研究 · data/a`、`研究 · data/b`。这段逻辑放在卡片文件内，无需通用路径缩写组件。

省略后仍重复时，主菜单使用原列表序号区分，列表卡使用已有序号，不重复编号。主菜单的序号仅辅助辨认，数字回复仍遵循原主菜单命令；按工作区序号切换只发生在独立工作区列表。序号不作为持久身份。

## 已确认的数据流

`HarnessClient.listWorkspaces()` 调用 `workspace.list` 后，仅抽取路径。现有客户端测试中的 RPC 样本已经包含 title，但返回给调用方的是 `string[]`。

飞书两个入口均经过 `workspacePathSnapshot()`。该函数检查目录是否存在、解析 `realpath`、去重，并将当前工作区放到首位。独立列表还将同一份 `paths` 保存在菜单中，供数字回复使用。

因此，名称必须随工作区一起经过路径校验和真实路径解析，不能单独再取一次列表后按数组下标拼接。两次请求可能取得不同顺序，也会增加不必要的 RPC。

## 五处代码调整

### 客户端保留工作区名称

文件：`src/channels/shared/harness-client.mjs`。

增加 `listWorkspaceEntries(options = {})`，沿用现有启动检查、超时、取消信号及 `workspace.list` RPC，只返回卡片需要的字段：

```js
[
  { path: '/data/research', title: '策略研究' },
  { path: '/data/chat', title: '' },
]
```

沿用现有绝对路径过滤规则；非法列表仍按现有行为返回空数组。title 不是字符串时视为空，不因为名称缺失丢弃有效工作区，也不传递 sessionIds 等无关数据。

`listWorkspaces(options)` 委托新方法，再映射出 `path[]`。它的参数、返回类型、顺序及错误传播保持兼容，每次读取仍只有一次 `workspace.list` RPC。

### 新方法接入现有机器人检查

文件：`src/channels/shared/bot-workspace-store.mjs`。

把 `listWorkspaceEntries` 加入目前包装 `listWorkspaces`、`listWorkspaceSessions` 等方法的同一条件分支，复用调用前后检查机器人是否仍属于当前接入实例的逻辑。无需新代理或新状态。

### 工作区快照按需携带名称

文件：`src/channels/shared/workspace-command.mjs`。

给 `workspacePathSnapshot()` 的 options 增加 `includeTitles`，默认 false。读取时先将这个本地选项从 RPC options 中取出，继续原样传递 signal 等已有选项。

```js
// 既有调用保持原来的返回结构
{ current, paths }

// 飞书使用 includeTitles: true
{ current, paths, titles }
// titles 是以最终真实路径为键、名称字符串为值的普通对象
```

开启时优先调用 `listWorkspaceEntries()`；如果调用方提供的 harness 没有新方法，则读取既有 `listWorkspaces()`，按无名称处理。这是方法缺失时的兼容，不在 RPC 失败后重复请求。

复用当前单路径的合法性、目录存在性及 `realpath` 检查，将每个输入条目转成 `{ path: 真实路径, title }` 后再去重。需要提取小函数时放在原文件内，避免维护两套路径验证。若多个条目指向同一个真实目录，沿用原来的路径顺序，名称取上游顺序中第一个有效名称。

最终先产生与现有规则一致的 `paths`，再把名称按真实路径放进 `titles`。当前工作区被补到首位时，如果登记列表中有对应名称就沿用，否则回退文件夹名。当前目录存在性、排序和 `assertWorkspaceScope()` 检查继续保留。

默认调用仍走原来的路径列表接口和返回结构，普通文本命令无需调整。

### 飞书两处入口传递名称

文件：`src/channels/feishu/bridge.mjs`。

`#sendMenuCard()` 和 `#showWorkspaces()` 都传入 `includeTitles: true`，并将得到的名称字典传给卡片。主菜单 context 增加可选的 `workspaceTitles`；独立列表调用扩展为 `workspaceListCard(paths, current, titles)`。

菜单中的数字回复数据仍保存同一份 `paths`。主菜单读取失败时继续使用现有“只展示当前工作区”降级，名称为空；独立列表失败继续走现有错误提示。卡片刷新复用带名称的 menuContext，避免新会话状态刷新后退回路径显示。

### 两个卡片复用标签生成

文件：`src/channels/feishu/feishu-cards.mjs`。

增加一个文件内共享标签函数，输入完整 `paths` 和可选 `titles`，按上述规则输出与路径顺序对应的标签及是否需要补序号的信息。两个卡片构建函数共同调用。

先按完整快照生成标签，再应用主菜单现有前 20 项限制，使同一快照中的重名判定与序号保持一致。列表卡保留现有编号；主菜单保留勾选标记和 `initial_index`。

路径解析使用 Node 内置路径工具：Windows 盘符和 UNC 路径使用 `path.win32`，POSIX 路径使用 `path.posix`。这里只负责显示分段，不转换用于切换的真实路径，且可在非 Windows 开发机测试 Windows 标签。

下面两种操作数据保持原样：

```js
// 下拉框
{ text: { tag: 'plain_text', content: label }, value: path }

// 列表按钮
{ action: `workspace:${path}` }
```

卡片新增参数均有空值默认，原有仅传路径的调用继续有效。名称修改只影响展示；重开菜单时读取新名称，不增加标题缓存或监听器。

## 实施范围

本次处理飞书主菜单和工作区列表的显示。切换成功回执已经包含完整路径，直接沿用，方便用户确认实际目录。

不增加详情卡、工作区重命名入口、名称切换命令、数据库迁移或新 RPC；不扩展其他渠道，也不借此调整列表分页、会话标题或工作区切换机制。22 字标签预算放在卡片文件内作为固定常量，无需用户配置。
